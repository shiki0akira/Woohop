## 2. 定位

### 2.1 一句話定位
> **明天就要帶破冰？打開就能帶。**
> 給帶領陌生人聚會的小組長，不用準備道具、不用背規則，前一晚選好，現場跟著手機帶。

### 2.2 定位的關鍵轉換
- ❌ 舊：「用手機玩的破冰遊戲」→ 收錄不用手機的遊戲會偏離定位
- ✅ 新：「**帶活動的人，不用準備就能帶**」→ 手機只是手段，不用手機的遊戲也能收錄，但每個遊戲都要提供「帶領輔助」，而不只是文字規則

### 2.3 與競品的差異

| 競品 | 他們解決的 | 不足 |
|---|---|---|
| 清單文、部落格（「十大破冰遊戲」） | 有哪些遊戲 | 準備、出題、計時、帶領都要自己來 |
| icebreaker-games.org | 遊戲規則庫＋獨立小工具（賓果產生器、轉盤、分組） | 工具和遊戲沒串在一起；以文字說明為主；偏企業／線上會議 |
| Kahoot | 問答互動 | 要事先出題，偏測驗不是破冰 |
| Jackbox | 派對遊戲 | 要付費、要大螢幕、以英文為主 |
| **Woohop** | **我明天怎麼帶** | 從「選遊戲 → 準備 → 現場帶完」一條龍，免註冊 |

### 2.4 營運目標（優先順序）
1. **服務教會、讓小組長輕鬆**（主要目標）
2. 流量起來後再考慮廣告收入（AdSense），見 §9

## 3. 使用者

### 3.1 主要使用者輪廓：小組長阿明
- 每週帶一群**彼此還不認識**的人聚會（起點：教會推廣的幸福小組）
- 不是專業主持人，有正職，**通常活動前一晚才有空找遊戲**
- 想要：今晚就決定、明天直接帶、大家玩完真的有聊到話
- 害怕：冷場、規則講不清楚、要準備很多東西
- 現在的做法：翻清單文，或乾脆重複玩以前玩過的那幾個

### 3.2 延伸市場
「一群陌生人要快速熟起來」是普遍需求：迎新、課堂、公司新人訓、營隊都適用。品牌不刻意標示教會色彩，教會是主要情境之一。

### 3.3 三個核心痛點
1. **時間壓力**：前一晚才臨時找，沒時間比較和讀長文章
2. **玩來玩去都一樣**：想不到新的，只好重複
3. **懶得準備**：需要道具或事前出題就會放棄，改玩更簡單的

## 4. 網站資訊架構

### 4.1 總覽

```
首頁 = 推薦器
 │  篩選：人數 / 時間 / 手邊有什麼 / 目的 / 大家熟不熟
 │
├─ 破冰帶領：不用手機的遊戲 + 帶領播放器
├─ 房間遊戲：每人一支手機，共用一套房間系統
├─ 桌遊助手：阿瓦隆，之後擴充其他桌遊（流量來源）
└─ 帶領指南：情境文章（SEO 入口，未來放廣告的主要位置）
```

### 4.2 四大區塊

| 區塊 | 內容 | 服務誰 |
|---|---|---|
| 首頁推薦器 | 輸入條件後推薦遊戲，進階版可推薦「一場聚會的組合」 | 前一晚才找遊戲的小組長 |
| 破冰帶領 | 不用手機的遊戲 + 帶領播放器（動畫教學、提詞、計時、轉盤） | 懶得準備、怕講不清楚的人 |
| 房間遊戲 | 喜好二選一、賓果、搶答…… | 想讓大家真的聊到話的場合 |
| 桌遊助手 | 阿瓦隆，之後可加狼人殺主持、誰是臥底等 | 搜尋進來的玩家 |

### 4.3 分類改為「標籤篩選」，不用主分類
舊的三個分類（遊戲工具／多人派對／快速破冰）其實是在描述「要幾支手機」，改為篩選條件之一，以便未來容納不用手機、主持人大螢幕等新型態。

**篩選維度：**

| 維度 | 選項 |
|---|---|
| 手機需求 | 不用手機 / 一支手機 / 每人一支 / 主持人大螢幕 |
| 人數 | 2–4 / 5–12 / 13–30 / 30+ |
| 時間 | 5 分鐘內 / 5–15 分鐘 / 15 分鐘以上 |
| 手邊有什麼 | 什麼都沒有 / 紙筆 / 投影或電視 / 手機 |
| **目的** | 暖場炒熱 / 認識彼此 / 深入分享 |
| 熟悉度 | 完全陌生 / 有點認識 / 很熟 |
| 場合 | 小組團契 / 課堂 / 公司 / 朋友聚會 |

### 4.4 「目的」維度與聚會流程
一群陌生人的聚會通常是 **暖場 → 認識 → 分享**：

- **暖場炒熱**：果園菜園動物園、竹筍竹筍蹦蹦出、上樓下樓、定時炸彈
- **認識彼此**：幸福賓果、喜好二選一、兩真一假
- **深入分享**：需要較熟才適合的問題（幸福模擬器不算在遊戲裡）

破冰在聚會裡只佔開頭一小段，**「排一場」只排暖場＋認識兩段，總長 10／15／20 分鐘**，不會排到一小時（2026-10-16）。

推薦器的進階功能：依據時間自動排出一場聚會的遊戲順序。

## 5. 核心功能規格

### 5.1 帶領播放器（Leader Player）— 最重要的元件

**核心觀念：做 1 個模板，不是做 100 個網頁。**
每個不用手機的遊戲只要填一份資料檔，就自動產生帶領模式。收錄新遊戲是「寫內容」，不是「寫程式」。

**手機在不用手機的遊戲中能做的事：**

| 時機 | 功能 | 解決的痛點 |
|---|---|---|
| 前一晚 | 步驟式動畫教學，按「下一步」，30 秒看完就會帶 | 時間壓力 |
| 開場 | 主持人提詞卡：照著念就好的規則說明 | 怕講不清楚 |
| 開場 | 教學畫面可投影或給大家看，主持人不用轉述 | 轉述不正確 |
| 進行中 | 節拍器（可加速），例如果園菜園動物園跟著拍子接 | 讓遊戲更刺激 |
| 進行中 | 隨機決定誰先開始、隨機指定主題 | 不用想 |
| 結束後 | 懲罰／分享轉盤：輸的人回答一個認識彼此的問題 | 把「暖場」轉成「認識彼此」 |
| 玩膩了 | 2–3 種變化玩法 | 玩來玩去都一樣 |

**設計原則：**
- 手機不介入遊戲本身（喊聲、動作、輪流接龍等），只輔助主持人
- 「結束後的分享轉盤」是讓暖場遊戲也能幫助認識彼此的關鍵

### 5.2 遊戲資料格式（草案）

```yaml
id: orchard-garden-zoo
slug: orchard-garden-zoo        # 網址用
name:
  zh-TW: 果園菜園動物園
  en: Orchard, Garden, Zoo
summary:
  zh-TW: 跟著拍子輪流說出水果、蔬菜或動物，卡住或重複的人就輸。
tags:
  phones: none                  # none | one | each | host-screen
  players: { min: 5, max: 20 }
  duration: 5-15                # 分鐘
  props: [none]                 # none | paper | projector | phone
  purpose: warmup               # warmup | getting-to-know | deep-sharing
  familiarity: [stranger, some]
  settings: [small-group, class, company, friends]
prep: 不需要任何道具
steps:                          # 動畫教學，每步一張
  - title: 圍成一圈
    text: 大家圍成一圈，主持人先開始。
    animation: circle-formation
  - title: 跟著拍子
    text: 拍兩下手，第三拍說出主題，例如「果園」。
    animation: clap-rhythm
  - title: 輪流接
    text: 下一個人跟著拍子說出一種水果，不能重複。
    animation: pass-turn
  - title: 誰輸了
    text: 卡住、說錯類別或重複的人就輸。
    animation: out
script:                         # 主持人提詞卡，照著念
  zh-TW: |
    我們等一下要玩「果園菜園動物園」。大家先跟我一起拍手……
tools:                          # 進行中可用的輔助工具
  metronome: { bpm: 90, speedUp: true }
  randomStarter: true
  randomTopic: [果園, 菜園, 動物園, 文具店, 便利商店]
afterGame:                      # 結束後的分享轉盤
  sharePrompts:
    - 你最喜歡的水果是什麼？為什麼？
    - 如果你是一種動物，你覺得你會是什麼？
variations:
  - name: 加速版
    text: 每輪拍子變快。
  - name: 淘汰制
    text: 輸的人出局，最後剩下的人獲勝。
```

### 5.3 房間系統（Room System）
- 目前搶答、喜好二選一、賓果各自有房間功能 → **整合成一套共用的房間系統**
- 共用功能：建立房間、房間代碼、QR code 加入、填名字（不註冊）、主持人控制（開始、踢人、關閉房間）
- 新增房間型遊戲時只需實作遊戲邏輯
- 「派對房間」（主持人開一次房、選遊戲／隨機／投票、整晚接著玩）
  - **2026-10-16 決定先做「大廳轉接」**：新增一個大廳房間，只管名單（名字、頭像）和選遊戲；選好後由大廳替大家在原本的遊戲裡開房，帶著名字和頭像把所有人送進去，玩完按「回大廳」回來。現有遊戲只要能接收帶進來的名字／頭像、加一顆回大廳
  - 之後整合成共用房間系統時，再把遊戲改成房間裡的模組；大廳的介面與流程不變

### 5.4 首頁推薦器
- 第一版：用 §4.3 的篩選條件過濾遊戲資料
- 第二版：依時間自動組合「暖場 → 認識」（10／15／20 分鐘）
- 不標示「上次玩過」（2026-10-16 決定拿掉，不記錄使用者玩過什麼）

### 5.5 暫緩的功能（等使用者變多再做）
- 會員、小組管理
- 「8 週聚會不重複的破冰清單」規劃功能
- 主持人大螢幕型新遊戲（類 Kahoot）

## 6. 視覺風格

### 6.1 方向
**溫馨可愛、幾何形大色塊、帶點童趣**。畫面一打開就讓陌生人放鬆。

### 6.2 原則
- **淺色背景為主**（取代目前的深色系）。頁面底色用**淺灰**，**不用純白 `#fff`**（2026-10-16 決定，參考使用者個人作品集網站的灰底）。卡片可以比底色亮一階，靠亮度差和柔和陰影浮出來，而不是整頁白
  - 參考值取自[作品集](https://shiki0akira.github.io/wen-portfolio/)的淺色主題：頁面底色 `#f4f4f6`、卡片 `#ffffff80`（半透明白疊在灰底上）、文字 `#111113`、分隔線 `#0000001a`、圓角 `20px`、陰影 `0 8px 32px #252c4b1a`
- 幾組飽和但柔和的大色塊，例如：橘、黃、薄荷綠、天藍、珊瑚粉；**從現有 W 色塊 logo 取色**
- 圓形、三角形、圓角方塊等幾何圖形作為裝飾
- **每個遊戲有自己的代表色和代表圖形**，在列表、遊戲頁、房間中保持一致
- 圓潤的字體；按鈕大、好按（現場單手操作）
- 色彩用 CSS 變數（design tokens）管理，方便日後調整

### 6.3 設計系統（2026-10-16 定案）
- 所有 UI 一律參考 [design/brand-exploration.html](../design/brand-exploration.html)：色票、按鈕、表單、導覽、房間、回饋、對話框、帶領播放器、插圖、頭像都在這一頁
- 要改視覺規則先改這一頁，再改各遊戲的實作

### 6.4 待辦
- 照設計系統做新首頁＋推薦器的設計稿，確認後再套用到其他頁面

## 8. 改版注意事項（重要）

- ⚠️ **阿瓦隆的網址 `/avalon/zh-TW` 不可更動**，它是目前主要的流量來源

## 9. 未來營利（AdSense）備忘

### 9.1 申請前要補
- **隱私權政策頁**（使用 AdSense 必須說明 Cookie 用途）
- 關於我們、聯絡方式頁（放頁尾）
- 工具頁增加文字內容（適用場合、帶領技巧、常見問題），避免被判為內容價值偏低

### 9.2 廣告位置原則
- ❌ 不放在遊戲進行中的畫面（尤其搶答按鈕、定時炸彈），容易誤點 → 無效點擊 → 可能停權
- ❌ 不放在主持人投影的畫面
- ✅ 放在首頁、玩法說明頁、遊戲結束的結果頁、帶領指南文章
- 不建議直接開「自動廣告」，或需排除遊戲頁面

### 9.3 收入預估
- 台灣中文流量每千次瀏覽收益約 NT$30–100（工具型網站可能偏低）
- 月入 NT$10,000 約需每月 10–33 萬次瀏覽（目前約 3,100 次）
- 英文及歐美流量收益較高，多語言是優勢
- 廣告以外可考慮：贊助按鈕、付費題庫、教會／企業客製版

## 10. 實作起手式

1. 先盤點現有程式碼：各遊戲的技術架構、房間功能如何實作、多語言如何處理、路由與網址結構
2. 定義遊戲資料格式（§5.2），把現有 6 個遊戲轉成資料檔
3. 建立 design tokens（§6），做新首頁＋推薦器
4. 確認所有舊網址仍可正常開啟後再上線
